# Review 工作流

## 目标

以只读方式识别进度、依赖、风险、决策和下一步行动问题，并在用户确认后应用必要更新。

## 前置条件

- 读取并校验当前状态。
- 明确 review 范围：整个项目、里程碑、迭代或指定工作项。

## 分析步骤

1. 检查逾期里程碑、迭代和工作项。
2. 检查长期停留在 `in_progress` 或 `review` 的工作项。
3. 检查 `blocked` 工作项是否具有明确解除条件。
4. 检查依赖冲突、不可满足的依赖和没有后续行动的工作。
5. 检查高风险、高概率风险和缺失缓解措施。
6. 检查已接受决策是否仍与当前计划一致。
7. 生成最多三个下一步行动，并说明优先级理由。
8. 总结“状态良好”“需要关注”“必须处理”三类结论。

## 写入规则

- 默认不修改状态。
- 只有用户明确接受建议时，才创建候选状态并增加 revision。
- review 写入仍遵循 [Update 工作流](update.md) 的证据和确认规则。

## Chat Mode

输出分析、建议的完整状态和 Git 建议，但明确说明没有修改文件。

## 示例

用户请求：“检查当前迭代是否还能按时完成。”

预期效果：报告逾期项、阻塞、风险和依赖问题；没有用户接受前 revision 不变。
